# Vocab-gap (S bucket) diagnosis — findings

**Question.** The held-out benchmark splits every query by lexical relationship
to its gold symbol: **L** (distinctive lexical overlap — the easy control) and
**S** (no distinctive overlap — the pure vocabulary/semantic gap). Lexical
(BM25) retrieval cannot *seed* on an S query by construction. This diagnosis
asks: **is the S bucket recoverable without shipping embeddings**, and if so,
what is the lever?

**Corpus.** All 76 frozen S-bucket queries across four persona snapshots
(Marlin 27, pandas 23, ripgrep 16, gin 10; remix has none). Same predicate as
`heldout_eval.py`: `strict_match` (word-boundary token match) on the gold
`qualified_name` appearing in the top-10.

## Arms measured

| Arm | Hit@1 | Hit@5 | Hit@10 | MRR |
|---|---|---|---|---|
| Baseline — lexical + graph, one-shot literal phrasing | 2/76 | 5/76 | **11/76 (14.5%)** | 0.051 |
| Reformulation — blind jargon variants, `--also`/RRF | 2/76 | 11/76 | **19/76 (25.0%)** | 0.076 |
| Reformulation — original question + variants, RRF | 3/76 | 10/76 | 18/76 (23.7%) | 0.084 |
| Offline dense (reference) — BGE-small, best-case pool | 2/76 | 8/76 | **8/76 (10.5%)** | 0.057 |

- **Baseline** is `roux query` with the raw human query (`heldout_eval.py`).
- **Reformulation** fires blind, agent-style jargon variants (generated by a
  stateless model given only repo domain + query text — never the gold; see
  `vocab_gap_blind_input.json` / `vocab_gap_variants.json`) via
  `roux query --also`, RRF-fused. Reproduces the method of `agent_reform_eval.py`,
  generalized from 8 hand-picked Marlin queries to all 76 frozen S queries.
  Run: `vocab_gap_reform.py`.
- **Offline dense** is a MEASUREMENT reference only — roux ships no embeddings.
  It ranks each query against BGE-small embeddings of every *code* symbol
  (file/doc_section structural nodes excluded — a best case for dense).
  Run: `vocab_gap_dense.py` (needs `fastembed` in a throwaway venv).
- **Doc cross-reference edges: not remeasured here.** `doc_section` nodes and
  doc-reference edges are already active in the frozen indexes, so their effect
  is already inside the baseline and reformulation numbers. Isolating them would
  require rebuilding no-doc-edge indexes from source; prior work already found
  doc→code bridging is gated by candidate-pool *seeding*, not node/edge
  modeling. It is therefore not a distinct lever and is excluded from the table.

## Findings

1. **The dense reference underperformed.** Even given its best-case pool, a
   strong general sentence-embedding model (BGE-small) reached only 8/76 —
   *below* the lexical+graph baseline (11/76) and well below reformulation
   (19/76). It recovered **zero** queries that reformulation missed: dense's
   hits are a strict subset of reformulation's, and it floors on the identical
   residual. On this diagnostic, a shipped embedding signal is not justified —
   it would underperform what roux already does. (Caveat: BGE-small is one
   strong *small* model; larger models are unmeasured. But a dense arm that
   loses to lexical baseline is strong directional evidence against the gap
   being embedding-shaped.)

2. **Reformulation is the lever.** Rephrasing the question into the code's
   jargon lifts S Hit@10 from 11/76 to 19/76 (+73% relative), ~2.4× the dense
   arm — and it is free: no shipped model, no GPU, consistent with roux's
   CPU-only/no-embeddings architecture. Because roux serves LLM agents, the
   caller performs this reformulation naturally; roux exposes it via `--also`
   (RRF fusion). Net movement vs baseline is +12 recovered / −4 regressed:
   variants-only maximizes Hit@10; adding the original question back trades a
   little Hit@10 for higher Hit@1/MRR (RRF dilution keeps the 23/76 set-union
   from being realized by naive fusion).

3. **The residual is not a retrieval problem.** The 53/76 that no arm reaches
   are dominated by *symptom-titled bug reports pinned to the fix-commit's
   touched symbol* — e.g. "Y Layer Shift when Skew Value is Set" → `check_axes_activity`,
   "EEPROM_CHITCHAT No Feedback?" → `postprocess`. The query describes a symptom;
   the gold is an internal function a maintainer changed to fix it. Bridging
   that is an *inference* task (symptom → root cause) requiring code
   understanding the query does not encode — unreachable by lexical, graph,
   reformulation, or dense alike; the dense reference in particular adds zero
   unique recoveries over lexical + reformulation.

## Verdict

The graph-native retrieval architecture (BM25/FTS5 seeding + PPR graph
expansion, two signals) is at its achievable ceiling **for the retrieval
task**. The portion of the vocabulary gap that is genuinely a rephrasing
problem is closed agent-side by reformulation; the remainder is a
symptom→root-cause inference task that no retrieval method addresses. A shipped
dense signal is not justified by this diagnostic and would break roux's
no-embeddings, CPU-only promise. **Chosen lever: agent reformulation via
`--also`/RRF.** Embeddings remain, at most, a later benchmark-driven question
against a stronger model — not a current gap.

## Reproduce

```sh
cargo build --release
python3 bench/heldout_eval.py                     # baseline, S/L split
python3 bench/vocab_gap_reform.py                 # reformulation arm

python3 -m venv /tmp/roux-dense-venv              # dense reference (measurement only)
/tmp/roux-dense-venv/bin/pip install fastembed numpy
/tmp/roux-dense-venv/bin/python bench/vocab_gap_dense.py
```
