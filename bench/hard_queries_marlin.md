# Hard vocabulary-mismatch queries — Marlin (roux-pc7u)

Authored to settle whether dense retrieval earns its keep. The only bucket that
tests embeddings is **S** (semantic-only): the gold symbol's full indexed text
(name + signature + doc-comment + body) shares **zero** lexical overlap with the
query's content words — *even after stemming* — so BM25 cannot seed it. It can be
won only by the graph (a lexical neighbor pulls it in) or by dense rerank. The
verdict: embeddings live iff they beat lexical+graph **materially on S**.

Buckets are pre-registered (classified from the code before any ranker runs), so
roux's own output can't shape the labels.

| bucket | definition | who should win |
|---|---|---|
| L | query/stem hits the symbol **name** | stemming (control) |
| B | terms in doc/body, not name | BM25-on-body (control) |
| S | concept present in the symbol's own words, zero query-lexical overlap | graph **or** embeddings — **the test** |
| U | concept not a named symbol / not in text | nobody — **excluded** |

Evidence per query was generated by extracting the gold symbol's ±25-line window,
lowercasing, splitting `_`, and checking each query content-word's **stem prefix**
(`ring`→`ring[a-z]*`) against name and body. `gap` = absent under stemming.

## Batch 1 — the query set

Machine source of truth: `bench/hard_queries_marlin.json` (8 S + 2 controls).
Run it: `python3 bench/hard_eval.py marlin --show`. Buckets verified against the
roux DB's actual indexed text, not raw source (raw-source windowing gave a false
"configuration" hit on M500 from a file-level `#include` roux doesn't attribute to
the symbol — the DB is ground truth).

S bucket: S1 ringing→M593, S2 heater-out-of-control→tr_state_machine,
S3 pressure→M900, S4 origin→homeaxis/G28, S5 spool-empty→FilamentMonitor,
S6 remember-after-power-off→M500, S7 sudden-jolts→M205, S8 nudge→Babystep.

Fairness-to-embeddings check (criterion: concept must be embeddable): every gold
carries the concept in its own vocabulary — M593 "input shaping/frequency/damping",
tr_state_machine "runaway/thermal protection", M900 "linear advance/K factor",
homeaxis "home/endstop", runout "filament/runout", M500 "store settings". A good
code-text embedding model can plausibly bridge each. None require external
knowledge absent from the symbol text.

```

L (control)    n=1  L1 #5   (input shaping frequency -> M593)
B (control)    n=1  B1 #3   (set the hotend temperature -> M104)
```

Controls pass (harness + index sound). S bucket is a **clean 0/8** — the graph
does NOT bridge vocabulary mismatch. Headroom for embeddings is real.

**Pool-membership probe (decides cheap-rerank vs full-ANN), top-400:**

| S query | gold rank in pool |
|---|---|
| detect when the spool is empty | #14 — in pool, just past 10 |
| shut down if heater out of control | #342 — present but practically absent |
| stop ringing/ghosting | ABSENT from top-400 |
| remember config after power off | ABSENT from top-400 |
| nudge nozzle height while printing | ABSENT from top-400 |

All these symbols exist in the index; they are simply not reachable from the
query's lexical seeds within 2 graph hops. **Consequence:** dense *rerank over the
BM25+2-hop pool* (bead roux-w6id, the latency-safe lever) recovers ~1/5 at best —
the rest are not in the pool to rerank. Moving the S bucket requires **full-corpus
ANN dense retrieval**, the latency-expensive path. The embeddings decision is
therefore "is full-corpus ANN worth the latency," not "cheap rerank or not."

Caveat: n=8 is direction, not verdict (per project discipline). The direction here
is stark and unlikely to reverse, but thicken to ~15+ S before committing to build.

## Rejection log (criteria actually filter — not cherry-picked)

- **M600 "pause the print to swap out filament" → REJECTED (is B, not S).** Doc:
  "M600: Pause for filament change" — both *pause* and *filament* present. Lexically
  reachable; would falsely credit embeddings.
- **G34 "keep both Z lead screws aligned" → REJECTED (is L via stemming).** Doc:
  "G34 - Align the ends of the X gantry" — "aligned"→stem "align" hits the doc.
- **junction-deviation "smooth out motion at sharp corners" → DROPPED.** The only
  named gold is a UI getter (`getJunctionDeviation_mm`); the actual cornering math
  is inline in `Planner` block computation (planner.cpp:~2700), not a named symbol.
  Lesson: roux indexes *symbols*; concepts living only in inline code are **U**
  (un-retrievable by construction, not an embeddings test). Dropped rather than ship
  a weak getter as gold.
- **M106 "blow air on the printed layer to cool it" → REJECTED (is B).** "cool" is
  in the body. **M420 "turn bed leveling on and off" → REJECTED (is L).** Query is
  literally the jargon. **maxtemp_error "sensor reads garbage" → DROPPED (meaning).**
  That path is over-temp, not sensor-disconnect; gold semantically shaky.

## DENSE RESULT (2026-06-24, e5-small-multilingual, full Marlin embed)

Wired `roux query --dense` (pure vector search) + populated all 13,396 vectors
(Metal, ~12 min). `python3 bench/hard_eval.py marlin --both`:

```
S (THE TEST)   lexical+graph 0/8 MRR 0.000   |   DENSE 0/8 MRR 0.000
```

Dense ties lexical at 0/8 and lost the B control. NOT a bug — diagnostic jargon
queries prove the pipeline works ("thermal runaway protection" -> RunawayIndex/
TRState/runaway_index_for_id; "set the hotend temperature" -> SetHotendTemp/
ApplyHotendTemp; "input shaping" -> shaping_isr/M593). The model finds the right
symbol *when the query contains the jargon* (those tokens are in the symbol text).

On the real non-jargon S queries it surface-matches instead of bridging concepts:
"ringing/ghosting"->stopPrint, "out of control"->minkill/shutdown, "pressure
buildup in nozzle"->set_nozzle/prime_nozzle, "origin"->tool_change/MoveTo, "spool
empty"->isEmpty/RingBuffer::empty, "power off"->power_off, "nudge"->NudgeNozzleUI.
It behaves like fuzzy BM25, not semantic understanding.

VERDICT (model-scoped, not approach-scoped): e5-small-multilingual (118M, general)
does NOT bridge vocabulary mismatch. This falsifies the weakest model, NOT
"embeddings can bridge this." Next fair test: a code/larger embedder (jina-code,
nomic-embed-code, gte-large) — one config change (DEFAULT_MODEL_ID) + re-embed.

Note: gold matchers are somewhat narrow (S2 should accept runaway/TRState/
RunawayIndex), but widening them doesn't change the verdict — the non-jargon dense
returns are conceptually wrong regardless of gold string.

## DOC-BRIDGE RESULT (2026-06-24) — the CPU win embeddings missed

Thesis: human-written docs carry the vocabulary the code lacks, next to backtick
refs that resolve to code symbols (doc_section --references--> code edge). So a
lexical query hits the doc, and the graph hops to the code — semantic bridging
with no model.

Validated by planting `bench/docbridge_marlin_fixture.md` in the Marlin tree (one
section per S query, each pointing at its gold symbol), re-indexing (all 8 refs
resolved), and adding opt-in doc-reference promotion (`ROUX_DOC_PROMOTE=1`):

```
S bucket:   lexical 0/8   |   e5 dense 0/8   |   doc-bridge+promotion 8/8 (Hit@5 & @10, MRR 0.500)
```

Every S gold lands at #2, right behind its explanatory doc. Reproduce:
`cp bench/docbridge_marlin_fixture.md /tmp/roux-sources/Marlin/ && (cd /tmp/roux-sources/Marlin && roux add . --lang cpp --local --name Marlin) && ROUX_DOC_PROMOTE=1 python3 bench/hard_eval.py marlin`

Promotion mechanics (rank.rs): when a *dominant* (≥0.9× top score) matched
doc_section with ≤3 refs bridges to a code symbol, lift that symbol to 0.95× the
doc score and rank it among the seeds; rescue-only (never re-rank a symbol already
in the natural top-k). Multiplicative score fusion zeroes bm25=0 nodes, so RRF
(`ROUX_FUSION=rrf`) is the companion lever.

OFF by default: validated only on planted docs, and it nicks one real persona query
(remix "file storage backend for sessions": a close-but-wrong *cookie*-session doc
dominates and promotes its refs, #3->#6). Personas with promotion OFF = baseline
(Hit@5 95%, MRR 0.791); ON = Hit@5 92%, MRR 0.787 (CI gate Hit@10/MRR still holds).
Productionizing needs doc-match precision + real-doc (non-planted) validation.
